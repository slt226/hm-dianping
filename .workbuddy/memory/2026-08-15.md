## 修复"服务器异常"：恢复本机黑马点评运行环境

### 现象
- 前端 8080 显示"服务器异常"（nginx 50x 页），无画面。
- 根因：MySQL(3307) 与 Redis(6379) 都没运行，后端连不上库 → API 500。

### 本机环境关键事实（重要，重启时必看）
- **MySQL**：phpEnv 自带 MySQL 5.7，位于 `D:\phpEnv\server\mysql\mysql-5.7`。
  - 端口 **3307**，root 密码 **root**（不是 123！application.yaml 已改为 root）。
  - **必须用 `--no-defaults` 启动**：my.ini 里 `log-error=C:/phpEnv/...` 指向不存在的 C 盘路径，正常启动直接失败。
  - 启动命令（后台）：
    `mysqld.exe --no-defaults --port=3307 --datadir="D:/phpEnv/server/mysql/mysql-5.7/data" --basedir="D:/phpEnv/server/mysql/mysql-5.7" --character-set-server=utf8 --explicit_defaults_for_timestamp=on --log-error="D:/phpEnv/server/mysql/mysql-5.7/logs/mysql.log"`
- **Redis**：`D:\redisconfig\redis-server.exe`，Redis 3.2.100，端口 6379，**密码 123321**（需 `--requirepass 123321` 启动，Windows 不支持 daemonize，要后台跑）。
- **后端**：8081，可用 `java -jar target/hm-dianping-0.0.1-SNAPSHOT.jar --server.port=8081 --spring.config.location=file:D:/heimadianping/hm-dianping/src/main/resources/application.yaml` 启动。
- **前端**：nginx 在 `D:\heimadianping\heimadianpingfront\nginx-1.18.0`，`./nginx.exe` 启动，8080 端口，`/api` 前缀去掉后转发 8081。

### 数据库导入
- hmdp 库此前从未建成（SQL 文件无 CREATE DATABASE/USE，且首次导入报 No database selected）。
- 导入需两步：先 `SET GLOBAL sql_mode=''; SET SESSION sql_mode='';`（否则 MySQL 5.7 报 `Invalid default value for 'begin_time'`），再 `CREATE DATABASE hmdp DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci; USE hmdp; SOURCE .../db/hmdp.sql;`
- 导入后 11 张表齐全：tb_user 1005 行、tb_shop 14 行。

### 坑：SERVER__PORT 环境变量劫持端口
- WorkBuddy 沙箱 bash 环境注入 `SERVER__PORT=55454`，Spring Boot 宽松绑定把它当 `server.port`，优先级高于 yaml，导致后端绑定 55454 并撞上占用端口启动失败。
- 解决：启动 java 时显式加 `--server.port=8081`（命令行参数优先级最高）。
- 用户从 IDEA 自己启动后端不受此影响。

### 验证结果
- `http://localhost:8080/` → 200，`<title>黑马点评</title>`
- `http://localhost:8080/api/shop-type/list` → 200，返回真实数据（Redis+MySQL 缓存链路正常）

## 短信验证码登录改造为 Redis 版（完成并验证）

原代码是半成品：RedisConstants 已定义 key/TTL，但验证码存取、登录态、拦截器全用 Session。已改为标准黑马点评 Redis 方案：

### 改动文件
- `UserServiceImpl`：sendcode 验证码存 `login:code:{phone}`（TTL 2 分钟）；login 从 Redis 校验验证码，成功后用 `IdUtil.fastSimpleUUID()` 生成 token，UserDTO 以 JSON 存 `login:token:{token}`（TTL 36000 秒=10 小时），返回 token。
- `IUserService` / `UserController`：去掉 HttpSession 参数；logout 实现为删除 `login:token:{token}` + 清 ThreadLocal。
- `LoginInterceptor`：改为从请求头 `authorization` 取 token → 查 Redis → 命中存 UserHolder 并刷新 TTL，未命中 401。构造器注入 StringRedisTemplate。
- `MvcConfig`：注入 StringRedisTemplate 传给拦截器。
- 前端 `common.js` 原本就支持：sessionStorage 存 token、axios 拦截器自动加 authorization 头，无需改动。

### 验证（curl 全链路通过）
- code 接口 → Redis 可见 `login:code:13800138000`
- login 正确验证码 → 返回 32 位 token；错误验证码 → "验证码错误!"
- 带 token 访问 /user/me → 返回用户；无 token → 401
- Redis `login:token:*` TTL 36000；logout 后 EXISTS=0，再访问 401
- 注意：验证码登录成功后未删除 Redis 验证码（与黑马点评原版行为一致，如需可加 delete）

### 坑
- `UUID.randomUUID().toString(true)` 编译不过（Java UUID 无 boolean 重载），改用 hutool `IdUtil.fastSimpleUUID()`。
- 旧后端进程运行中会锁住 jar，`mvn package` 报 Unable to rename，需先杀 8081 进程再打包。

## Bug 修复：Redis 登录 token 存储语句缺失（已修复并验证）

用户多次追问"redis存储代码"后确认：`UserServiceImpl.log()` 第 85-86 行注释写"8.3.存储到 Redis"但 **set 语句缺失**——token 生成、UserDTO 转换后没有真正写入 Redis，导致前端拿 token 访问接口永远 401，登录态无法建立。

- 修复：补上 `stringRedisTemplate.opsForValue().set(LOGIN_USER_KEY + token, JSONUtil.toJsonStr(userDTO), LOGIN_USER_TTL, TimeUnit.SECONDS);`
- 教训：**"注释写了但代码没写"的半成品代码是本次 bug 根源**，检查存储类代码时不能只看注释，要核对实际语句。
- 修复后 curl 全链路验证通过：发码 → Redis 读到验证码 → 登录返回 token → Redis 中 `login:token:{token}` 有 JSON 用户数据且 TTL=36000 → /me 正常 → logout 后 EXISTS=0。

## 双拦截器方案：解决登录状态刷新问题（完成，编译通过）

单拦截器方案的问题：LoginInterceptor 只拦截需登录路径，用户一直逛公开页（/shop/**、/blog/hot 被放行）时 token 永不刷新，活跃用户 10h 后仍被踢下线。

### 改动
- 新建 `RefreshTokenInterceptor`（order=0）：拦截 `/**` 全部路径，取 authorization token → 查 Redis → 命中则存 UserHolder + `expire` 刷新 TTL 10h；未命中/无 token 一律放行；afterCompletion 清 UserHolder。
- `LoginInterceptor`（order=1）简化为纯校验：不再注入 StringRedisTemplate，只 `UserHolder.getUser() == null` → 401。
- `MvcConfig`：`registry.addInterceptor(new RefreshTokenInterceptor(stringRedisTemplate)).addPathPatterns("/**").order(0)`；`new LoginInterceptor().excludePathPatterns(公开路径).order(1)`。

### 执行顺序说明
Spring 拦截器 order 越小越先执行 preHandle；afterCompletion 逆序（Login 先清、Refresh 后清，removeUser 幂等安全）。

- 用户当前从 IDEA 运行后端（8081 被 IDEA 占用），改完代码后需在 IDEA 重启生效，命令行启动会撞端口。

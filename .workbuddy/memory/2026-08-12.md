## Nginx 启动成功但看不到页面 — 端口诊断

### 问题
用户反映 Nginx 成功启动但浏览器看不到黑马点评页面。

### 根因
- **端口不匹配**：黑马点评的 Nginx 配置（`D:/heimadianping/heimadianpingfront/nginx-1.18.0/conf/nginx.conf`）监听 **8080** 端口，不是默认的 80。
- **80 端口被 IIS 占用**：Windows 系统进程（PID 4，IIS）监听 80 端口，用户访问 `http://localhost`（默认 80）看到的是 IIS 默认页面，不是 Nginx 的。
- Nginx 配置：`listen 8080`，`root html/hmdp`，`/api` 反代到 `http://127.0.0.1:8081`（Java 后端）。

### 验证
- `curl http://localhost` → HTTP 200，`<title>IIS Windows</title>`（IIS 默认页，不是 Nginx）
- `curl http://localhost:8080` → HTTP 200，`<title>黑马点评</title>`（Nginx 正常服务）
- 后端 Java 服务在 8081 正常运行（PID 7784）
- Nginx 有 6 个进程在跑（多次启动导致），实际监听 8080 的有 3 个

### 解决方案
浏览器访问 **`http://localhost:8080`** 即可看到黑马点评页面。

### 额外提醒
- Nginx 有 6 个进程，说明被多次 `start nginx`。可通过 `nginx -s stop` 或 `nginx -s quit` 停止后重新启动一次。
- 另有 phpEnv 的 Nginx（`D:/phpEnv/server/nginx`）监听 80 端口，与 IIS 冲突但与本项目的 8080 无关。

## 前端"服务器异常"+ 页面无图片 — Redis/MySQL 未启动 + Nginx 多实例冲突

### 问题
用户访问 `http://localhost:8080`，页面能打开但显示"服务器异常"，且没有图片和样式。

### 根因（两个独立问题叠加）
1. **Redis（6379）和 MySQL（3307）未运行**：电脑重启或手动关闭后，这两个服务没自启。后端 Java（8081）虽然在跑，但连不上数据库和缓存，所有接口返回 `{"success":false,"errorMsg":"服务器异常"}`。前端 common.js 的 axios 拦截器在后端返回 non-success 时 reject("服务器异常")。
2. **Nginx 6 个进程来自 3 个不同安装**：`heimadianpingfront/nginx-1.18.0`、`phpEnv/server/nginx`、`software/beforeenvirnoment/nginx-1.20.2`，互相冲突。

### 修复步骤
1. 启动 Redis：`D:\redisconfig\redis-server.exe --port 6379 --requirepass 123321`（后台）
2. 启动 MySQL 3307：`"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" --port 3307 --datadir="C:/Users/HP/mysql-hmdp/data" --console`（后台）
3. `taskkill /F /IM nginx.exe` 杀掉所有 6 个 nginx 进程
4. 从项目目录 `cd /d/heimadianping/heimadianpingfront/nginx-1.18.0 && ./nginx.exe` 干净启动（1主1从=2进程）
5. 验证：所有静态资源（CSS/图片）和 API 均正常返回正确字节数

### 验证结果
- index.html: 5238 bytes ✅
- index.css: 1646 bytes ✅ | main.css: 992 bytes ✅
- ms.png: 2780 bytes ✅ | blog1.jpg: 65123 bytes ✅
- /api/shop-type/list: 652 bytes, success:true ✅
- /api/blog/hot?current=1: 6046 bytes, success:true ✅

### 注意
- `curl -w "%{size_download}"` 在 Git Bash 显示 0 是假象，用 `curl -s URL | wc -c` 验证真实字节数。
- 用户需 **Ctrl+F5 硬刷新浏览器** 清除之前缓存的错误状态。
- 启动顺序很重要：先 Redis + MySQL，再 Java 后端，最后 Nginx。
